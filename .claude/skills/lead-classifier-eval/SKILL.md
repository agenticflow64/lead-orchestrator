# lead-classifier-eval

Прогон тестового набора через классификатор заявок и подсчёт метрик.

## Вход

- Набор заявок: `docs/test-leads.md` (таблица с колонками: текст, ожидаемый тип, ожидаемая срочность).
- Классификатор: `app/classifier.py`, ключи из `.env` (`OPENROUTER_API_KEY`, резерв `GLM_API_KEY`).
- Прогон: `set -a; source .env; set +a; .venv/bin/python scripts/eval_dataset.py`
  (режимы: LLM по умолчанию, `--rules` — regex-fallback, `--api` — через запущенный HTTP-сервис).

## Процесс

1. Запустить `scripts/eval_dataset.py` (скрипт сам парсит набор и печатает метрики). Для каждой заявки фиксируются:
   - предсказанный `type`, предсказанный `urgency`;
   - извлечённые `name` / `contact` / `summary`;
   - время вызова, сек.
2. Сравнить с ожидаемыми значениями из таблицы набора.
3. Посчитать метрики:
   - точность по типам: `accuracy` общий + разбивка per-type;
   - точность по срочности: `accuracy` общий (отдельно для `high` — она важнее);
   - полнота извлечения полей: доля заявок, где поле извлечено верно (пустое поле считается верным, если его нет в тексте; выдуманное — ошибкой);
   - время классификации: среднее.
4. Собрать сводную таблицу: одна строка на заявку (ожидание / предсказание / совпадение) + блок итоговых метрик.

## Правила

- Результаты — с пометкой «демо, локальные замеры».
- Не подгонять промпт под конкретные ошибки в этом же прогоне: правка → отдельный повторный прогон всего набора.
- Спорные случаи (например, жалоба против техподдержки) отметить отдельно, не молча засчитывать ошибкой.
- Сырые ответы LLM сохранить рядом с таблицей (для разбора ошибок).
