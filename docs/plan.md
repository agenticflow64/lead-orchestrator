# План по вечерам

Три вечера по 2–3 часа. Цель каждого вечера — рабочий инкремент, который можно показать.

## Вечер 1 — каркас: n8n + webhook + эхо

- [ ] `docker compose up -d`, n8n на http://localhost:5678
- [ ] Создать бота в @BotFather, токен в `.env`
- [ ] Workflow: Telegram Trigger → ответ-эхо в чат («заявка принята»)
- [ ] Проверить: сообщение боту → эхо возвращается

**Результат вечера:** заявка доходит до n8n и возвращается подтверждением.

## Вечер 2 — классификация + Sheets + уведомление

- [ ] Python-функция классификации на GLM API (`GLM_BASE_URL` + `GLM_API_KEY` из `.env`):
      тип, срочность, извлечение имени / контакта / сути
- [ ] Подключить функцию в workflow (HTTP-вызов или Code-нода)
- [ ] Запись в Google Sheets (credentials из `GOOGLE_SHEETS_CREDENTIALS_FILE`); если не готовы — таблица-загушка
- [ ] Уведомление ответственному (`TELEGRAM_CHAT_ID`), для `high` urgency — пометка «СРОЧНО»
- [ ] Фильтр спама: пометка в реестре, без уведомления

**Результат вечера:** полный контур из README работает end-to-end.

## Вечер 3 — тестовый набор, замеры, упаковка

- [ ] Прогнать `docs/test-leads.md` через классификатор (скилл `lead-classifier-eval`)
- [ ] Дозаполнить набор до ~30 заявок, если 15 мало для уверенных метрик
- [ ] Замерить: время обработки (сообщение → строка в таблице) по каждой тестовой заявке
- [ ] Посчитать: точность классификации по типам, полноту извлечения полей
- [ ] Записать демо по `docs/demo-script.md` (команда `/demo`)
- [ ] Обновить «Результат» в README + кейс в портфолио (команда `/case-update`)
- [ ] Финальный коммит, пуш в `agenticflow64/lead-orchestrator`

**Результат вечера:** цифры в README с пометкой «демо», записанное демо, кейс в портфолио.
