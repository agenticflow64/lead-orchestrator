# Тестовый набор заявок

Набор для проверки классификатора (все заявки вымышленные). Ожидаемые значения зафиксированы
заранее — по ним считается точность (`scripts/eval_dataset.py`, скилл `lead-classifier-eval`).
Объём — 15 заявок, все типы покрыты.

Прогон (демо, локальные замеры): LLM `nvidia/nemotron-3-super-120b-a12b:free` — 15/15 по типу,
15/15 по срочности, 30/30 по полям; regex-fallback — те же 15/15. Сырые ответы — `data/eval_results.json`.

Типы: `price_question` — вопрос о цене, `support` — техподдержка, `complaint` — жалоба,
`partnership` — сотрудничество, `spam` — спам.
Срочность: `low` / `medium` / `high`.

Примечания к сложным случаям (проверяем именно на них):

- №8 — жалоба, но без типа в лоб: проверяем отделение `complaint` от `support`.
- №7 — нет ни имени, ни контакта: извлечение полей должно вернуть пустые значения, а не выдумывать.
- №12 — контакт внутри текста как `@maketalk`: проверяем извлечение нестандартных контактов.
- №3 — только имя, без контакта: частичное извлечение полей.

## Формат прогона

Для каждой заявки фиксируем: предсказанный тип, предсказанную срочность, извлечённые
`name` / `contact` / `summary`, время обработки. Итог — сводная таблица метрик
(скилл `lead-classifier-eval`), цифры — с пометкой «демо».
